# Edge cases

Each row is a host condition that broke something during the research or the
build, what errand-box does about it, and the test that proves the fallback.
The code cites these by number (`E-NN`).

"Seen" names where the condition was measured: `research` for the research
branch of agent-box (`research/errand-sandbox/`), and `build` for the session
that wrote errand-box. [research/engines.md](research/engines.md) holds the
numbers. A test named `module::test` is a Rust unit test (`cargo test`); a
test named `live:` is a step of [tests.md](tests.md) section 3, which needs a
host with Incus.

| id | condition | effect | what errand-box does | test |
| --- | --- | --- | --- | --- |
| E-01 | No init on the host: PID 1 is a platform process | Nothing starts or restarts a daemon | `up` installs s6 and starts `s6-svscan`, which keeps every daemon running | `supervise::tests::s6_script_drops_privileges_and_execs`; live: up after a restart |
| E-02 | The host restarted | Device modes, kernel settings and every daemon are lost; disk state stays | `up` puts all of it back, and is safe to run again. Seen in build: a restart at about 07:40Z | live: up after a restart |
| E-03 | `/dev/fuse` and `/dev/net/tun` boot at mode 0600 | FUSE and tun inside guests fail | `up` sets mode 0666 at every run | live: up after a restart |
| E-04 | cgroup v1 | Incus 7.0 and later, podman 6, LXC 7 and systemd 258 and later refuse it; podman inside a guest cannot create cgroups | `engine.incus = auto` pins the 6.0 LTS line on a v1 host and says so; the guest's boot step sets podman to `cgroups = "disabled"` on v1 | `host::tests::channel_follows_cgroup_version`; live: podman inside |
| E-05 | An Incus `dir` storage pool | `root.size` is accepted and not enforced | The default pool is btrfs; `pool_driver = "dir"` is reported as degraded | live: quota |
| E-06 | No lxcfs | A guest sees the host's memory and CPU count in /proc | `up` runs lxcfs under the supervisor | live: lxcfs |
| E-07 | The LXC mount hook path differs by packaging | lxcfs at the wrong path is never bound into guests | `up` reads the installed hook (`/var/lib/lxcfs` or `/var/lib/incus-lxcfs`) and runs lxcfs there | `layout::tests::hook_paths` |
| E-08 | `/proc/1/personality` cannot be read, even by root | lxcfs 6 refuses every /proc file, and each guest start fails in the mount hook | `up` uses an installed lxcfs older than 6, or runs none and reports degraded | `up::tests::lxcfs_6_is_refused_where_pid1_personality_is_hidden` |
| E-09 | `df` in a guest on a btrfs pool | Shows the pool size, not the quota | Stated; the quota is still enforced | (documented) |
| E-10 | The host's egress proxy listens on 127.0.0.1 and allows CONNECT only | A build guest cannot reach it; plain-http apt gets 405 | The image build relays the proxy onto the build bridge for its duration; apt uses https | `image::tests::loopback_proxies_need_a_relay`; live: image build |
| E-11 | The Incus client with stdin open | It reads instance YAML from a non-terminal stdin and blocks until it closes (measured: 23 ms with stdin closed, blocked past 60 s with it open) | Every call closes stdin and has a deadline | `run::tests::stdin_is_closed_by_default`, `run::tests::a_deadline_kills_a_hung_program` |
| E-12 | A signal to incusd by name | Every guest's monitor is also named `incusd`, so the guests stop | Daemons are stopped only through their supervisor, which signals by pid. No code signals by name | `scripts/check-no-kill-by-name.sh` |
| E-13 | The egress proxy port moves across a restart (seen twice: 33337 to 42151, and 45823 to 44687) | A relay or daemon with the old port gets no answer | `up` reads `HTTPS_PROXY` on every run and rewrites `/etc/errand-box/proxy.env` | `up::tests::proxy_env_from_the_environment` |
| E-14 | `apt-get update` exits 0 when every fetch failed | A later install fails far from the cause | setup and the image build check `apt-cache policy` for the expected origin | live: setup, image build |
| E-15 | The proxy CA is at a platform path, and a bundle of many certificates is skipped by `update-ca-certificates` | TLS through the proxy fails in the guest | `network.proxy_ca` (or `PROXY_CA`) names one CA file; apt uses it through `Acquire::https::CaInfo`; it is removed from the image after the build | live: image build |
| E-16 | Docker Hub rate limits anonymous pulls (429) | `docker pull` in guests fails | The guest's Docker uses `image.registry_mirror` (default `mirror.gcr.io`) | live: docker inside |
| E-17 | No AppArmor in the kernel | Incus loses the AppArmor profile it adds | Reported as degraded; seccomp and isolated uid ranges remain | `errand-box doctor` |
| E-18 | Root lacks CAP_SYS_RESOURCE | Sysbox fails; Incus does not | Reported | `errand-box doctor` |
| E-19 | `security.idmap.isolated=true` | Each instance has its own uid range | Set for every session; with idmapped mounts (E-20) it costs nothing | live: golden copy |
| E-20 | Incus 6.0.0 (Ubuntu 24.04's package) never writes the map of the user namespace it probes idmapped mounts with, so the kernel answers EINVAL | Every new isolated instance rewrites its rootfs: 2.1 to 2.7 s instead of 0.4 to 0.5 s | setup installs Incus from the Zabbly repository where it can, and reports 6.0.0 as degraded | `setup::tests::versions` |
| E-21 | A `root.size` below the space the instance already uses | The instance can neither stop cleanly nor start ("Failed clearing ownership: disk quota exceeded") | `box.disk` below 4 GiB is refused | `config::tests::a_disk_quota_below_the_image_is_refused` |
| E-22 | errand's broker connects to its targets directly | On a host whose only egress is an HTTP proxy, guest traffic through errand's broker fails | Stated in [design.md](design.md); errand-box does not change errand | (documented) |
| E-23 | A rootless incusd lives in a network namespace of its own | A proxy device cannot reach host 127.0.0.1 | The shim relays the broker through a unix socket (`broker_link = "unix"`) | `relay::tests::unix_socket_reaches_a_tcp_server` |
| E-24 | Rootless Incus on btrfs | `btrfs qgroup limit` needs root, so no disk quota | Reported as degraded in rootless mode | (documented in [research/rootless.md](research/rootless.md)) |
| E-25 | A btrfs pool on a loop file | Space freed inside a guest returns to the host only after `fstrim` | `maint` runs `fstrim` on the pool every `maintenance.fstrim_hours` | live: maint |
| E-26 | `incus image copy` between two projects of one server | Fails: "The source server isn't listening on the network" | setup exports the image and imports it into errand's project | live: setup |
| E-27 | The session launcher is killed with SIGKILL | The guest process dies with the client, but the instance keeps running | A watchdog in its own session stops the instance when the launcher's pipe closes; `maint` reaps what both miss; `boot.autostart=false` stops a restart from reviving it | `session::tests` (lease), live: SIGKILL |
| E-28 | incusd restarts, after a host restart, every instance that was running | A session instance runs with no launcher | The project profile sets `boot.autostart=false` | live: setup |
| E-29 | `incus exec --user N` gives the process no supplementary groups | The agent is not in the guest's `docker` group, so `docker` gets "permission denied" on its socket. Seen in build | The shim runs the launcher as the guest's root; the launcher drops to the agent with `setpriv --init-groups` | `session::tests::exec_args_start_the_launcher_in_the_workspace`; live: docker inside |
| E-30 | The guest has 65536 ids, and a restricted project forbids a larger `security.idmap.size`; the guest has no default route | Rootless podman as the agent has no subordinate range ("cannot set up namespace using newuidmap"), and then pasta fails ("Couldn't set IPv4 route(s) in guest"). Seen in build | The image gives the agent ids 1001 to 65535 and makes slirp4netns the rootless network; an image file owned by an id above 64535 needs `sudo podman` | live: podman inside |
| E-31 | A new errand-box changes a file of the guest image, such as the launcher | An old image or an old session instance runs a launcher that does not match the shim | The image records a digest of its inputs; setup rebuilds an image whose digest differs, and a session remakes a stopped instance made from an older image | `image::tests::the_inputs_digest_follows_every_input`, `session::tests::prepare_remakes_a_stopped_copy_of_an_older_image`; live: setup |
| E-32 | The loop file of the pool is sparse, and the host disk has less free space than the pool can still grow | When the host disk fills, every guest gets I/O errors. Seen in build: a 20 GiB pool on a disk with 14 GiB free | setup reports it as degraded with both numbers; `engine.pool_size` sets a smaller pool | `setup::tests::a_loop_pool_larger_than_the_free_disk_is_reported` |
| E-33 | PID 1 does not reap orphans (a platform process, not an init) | A daemon that exits stays a zombie with its pid and start time, so a `pid:starttime` lease still reads alive. Seen in build: s6-svscan stopped, and `up` kept reporting it as running while every daemon was down | A lease whose process is a zombie counts as dead | `procs::tests::a_zombie_lease_is_dead`; live: up after a restart |
| E-34 | The daemons start together, after a restart or under s6 | incus-user and errand exit while incusd is not answering yet, and `up` read the restarts as a crash loop. Seen in build | Each daemon's run script first runs `errand-box __wait`: incusd waits for lxcfs to serve, incus-user and errand for incusd to answer `GET /1.0`; `up` starts all, then watches them together until each keeps one pid for 3 s | `up::tests::daemons_wait_for_the_ones_they_need`, `up::tests::a_service_settles_only_on_a_steady_pid`, `up::tests::readiness_checks`; hosts: every host |
| E-35 | Alpine's incus package creates neither `incus-admin` nor `incus` | incusd refuses to start ("unknown group incus-admin"). Seen in build on Alpine 3.22 | setup and `up` create both system groups when missing | hosts: alpine |
| E-36 | OpenRC is the init (Alpine) | Nothing runs `errand-box up` at boot, and the incus package's own OpenRC services would start a second incusd | setup writes `/etc/local.d/errand-box.start`, adds `local` to the default runlevel, and takes `incusd`, `incus-user` and `lxcfs` out of the runlevels; `doctor` reports the init | hosts: alpine restart |
| E-37 | The packaged lxcfs unit has `ConditionVirtualization=!container`, and Zabbly's incus.service `Requires=` it | On a host that is a container the unit is skipped, so guests get no lxcfs; stopping the unit stops incusd with it. Seen in build: an earlier fix that disabled it stopped incus.service mid-build | A drop-in clears the condition, sets the chosen lxcfs (E-08) or a condition that is never met; the unit is never stopped or disabled | `up::tests::the_lxcfs_drop_in_never_stops_the_packaged_unit`; hosts: u2404, deb13 |
| E-38 | A proxy that re-signs some TLS connections and passes others through | apt with only the proxy's CA fails every passed-through fetch; the same 13 packages failed in two runs. Seen in build | The image build gives apt the public roots plus the proxy's CA | hosts: u2404 image build |
| E-39 | An image build interrupted or failed after its instance started | `eb-build-<pid>` instances stay, and come back after a restart | The build deletes its instance on every path, and deletes old ones whose errand-box is gone before it starts; a running one stops the second build | hosts: setup |
| E-40 | errand's state root is missing (a disk not mounted, a moved home) | `gc` counted every session as deleted by errand and deleted them all | With the root missing, only age counts; `gc` takes each session's lock and looks again before it deletes | `maint::tests::stale_picks_old_and_orphaned_stopped_instances_only` |
| E-41 | The host restarts, or `up` runs, more often than `fstrim_hours` | The trim timer started at zero each time, so it never ran | `maint` keeps the last trim and gc times in `/var/lib/errand-box/maint-last` | `maint::tests::the_last_run_record_parses` |
| E-42 | The live configuration no longer parses (a typo after an edit) | `up`, the recovery after a restart, refused to run, so no daemon came back | setup keeps the configuration it applied in `/var/lib/errand-box/applied.toml`; `up` falls back to it and reports degraded. A `--config` that names a missing file is an error, not the defaults | `config::tests::a_named_config_file_must_exist` |
| E-43 | A session id `golden` | Its instance name is the golden instance | Ids that land on `eb-golden` or `eb-golden-*` get the digest form | `session::tests::names` |
| E-44 | apt sources use `http://` and the proxy allows CONNECT only | `apt-get update` fails with no hint at the cause | setup's failure names the cause and says to switch the sources to https | (message) |
| E-45 | No network, on a host where Incus is installed | setup failed at `apt-get update`, so a new config or new credentials could not be applied | A failed package refresh is degraded when Incus is installed; setup installs with `--no-upgrade`, so a second run does not upgrade Incus under running sessions | `setup::tests::apt_counts_what_it_installed` |
| E-46 | The build proxy URL carries credentials | They were on the argv of `incus exec`, readable by any local user, and the loopback relay dropped them | The settings go to the build instance as a 0600 file; the relayed URL keeps its credentials; proxy.env is 0600 and quoted, and refuses shell metacharacters | `image::tests::build_settings_are_a_file`, `relay::tests::a_relayed_proxy_keeps_its_credentials`, `up::tests::proxy_env_from_the_environment` |
| E-47 | A firewall drops forwarded traffic (Docker sets FORWARD to DROP; ufw denies routing) | The build instance gets no network | The failure names the likely cause | (message) |
| E-48 | A package upgrade replaced s6-svscan's program while it runs | `/proc/PID/exe` reads `PATH (deleted)`, and `up` replaced the whole tree, restarting incusd | A deleted program is the same program | `up::tests::a_replaced_program_is_the_same_program` |
| E-49 | setup installs a new errand or errand-box, or a new proxy | The running daemon keeps the old program or proxy | The run script or unit of errand and maint carries a digest of the files it read at start, so `up` restarts it when one changes; `status` reports a daemon whose program was replaced | `up::tests::a_stamp_follows_the_files_it_names` |
| E-50 | Two of setup, up, image build or uninstall at once | They race on the supervisor, the golden instance and the image alias | Each takes `/run/errand-box/host.lock`; the second waits | (main) |
| E-51 | A service leaves the list (lxcfs when E-08 forbids every lxcfs) | Its old s6 run script keeps running | `up` stops and removes service directories that are no longer in the list | hosts: alpine |
| E-52 | A derivative (Linux Mint, Pop!_OS) or a release newer than this program | No Zabbly suite matched, and the distribution's Incus was used | Codenames come from VERSION_CODENAME, then UBUNTU_CODENAME and DEBIAN_CODENAME; an unknown one is used when Zabbly's repository has it | `host::tests::a_derivative_gets_the_suite_of_its_base` |
| E-53 | Root's subordinate ids hold few 65536 blocks | Every isolated instance, stopped ones too, needs a block; creation fails once they run out | setup reports how many instances root's ranges hold, degraded below 64 | `setup::tests::isolated_capacity_counts_root_blocks` |
| E-54 | setup, as root, chowns and writes under errand's home, which the errand account owns | A symlink planted there redirects root's chown or write to any file | Each directory there is checked: a symlink is removed, the directory made, and `lchown` used | `setup::tests::safe_dir_replaces_a_symlink_and_leaves_its_target` |
| E-55 | The downloaded Zabbly key file holds more keys than Zabbly's | apt would trust each of them for the Zabbly source | The file must hold exactly one primary key, with the pinned fingerprint | `setup::tests::a_keyring_with_extra_keys_is_refused` |
| E-56 | A session's instance is running with no live launcher | The next run reused it, carrying the dead session's processes | The run stops it and starts it clean | (session) |
| E-57 | One instance will not stop or delete | `reap` or `gc` stopped the whole pass, and gc waited another day | The pass reports it and goes on | (maint) |
| E-58 | PID 1 does not reap (E-33) | Each session's watchdog stays a zombie after it exits, one pid each | Recorded; the instance itself is stopped by the watchdog or by `reap`. Not fixed: the watchdog must outlive the launcher that is its parent | (documented) |
| E-59 | setup changes `keep_days`, the pool or the project while maint runs | maint kept the old values | maint reads the configuration and runtime.toml on each pass | (maint) |
| E-60 | Incus reports `Ready` for a running guest that signalled readiness | It counted as not running | `Ready` counts as running | `incus::tests` |
| E-61 | errand's project allows proxy devices, for the broker link | The errand account can point a proxy device at any host socket, the Incus admin socket included, which is more than the restricted project grants it. Measured in build. Not reachable from a guest: a guest cannot add devices | Recorded as T-020; a project that forbids proxy devices refuses root's too, so the fix is a broker link without them | (documented) |
| E-62 | Newer s6-svstat prints `up (pid N pgid N)` | The pid read as none, so every daemon looked like a crash loop. Seen in build on Alpine 3.22 | The first number after `(pid ` is the pid | `supervise::tests::svstat_lines` |
| E-63 | No process limit on a guest | A fork bomb in one session can take every pid of the host, and `bailey doctor` said pids were limited | The profile sets `limits.processes` from `box.pids` (8192; 0 for none); `bailey doctor` reports the limits the profile really holds | live: doctor |
| E-64 | A host already has one Zabbly Incus line configured, and `engine.incus = auto` would pick another | A second setup moves it: lts-6.0 to stable on a cgroup v2 host (an upgrade), or the other way | `auto` keeps the configured line unless this host cannot run it (the `stable` line on cgroup v1) | (setup) |
| E-65 | incusd under s6 inherits the file and process limits of whoever ran `up` | Fewer open files and processes than the packaged service managers give it (1048576, unlimited), so a busy host hits the limit | The incusd run script raises both before it execs | (up) |
